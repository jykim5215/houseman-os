# UI_CANDIDATES.md — UI 시안 후보 비교와 추천 (v2 · NotebookLM 디자인 언어)

> **v2 개정**: 사용자 요구(2026-07-22, CLAUDE_CODE_PROMPT_v2_UI.md)에 따라 UI 정보구조를 NotebookLM(Gemini Notebook) 안드로이드 앱 계승으로 교체했다. 공통 골격: **하단 3탭(챗 / 소스&데이터 / 스튜디오) · 챗이 기본 화면 · Outlined 단선 아이콘 · 단일 강조색 · 다크 모드 · 큰 라운드 + 테이블 내부는 밀도 유지**. 세 후보의 차이는 **현장 운영 정보(상태판)를 얼마나 앞세우느냐**뿐이다.
> v1 시안(style-a-command-center / style-b-excel-ops / style-c-chat-first)은 참고용으로 폴더에 남겨두었으며 선택 대상이 아니다.

세 시안 모두 실제 더미 데이터, 번호형 출처 칩([1][2] → 근거 열람), 출처 충돌 경고, 고객용/내부용 분리 답변, 승인형 편집 카드(승인/취소), 추천 질문 칩, 음성 입력 버튼, 다크 모드 토글이 클릭 가능한 상태로 들어 있다.

## Style A — Notebook Classic (`style-a-notebook-classic.html`)
**가장 순정 NotebookLM.** 챗 상단에 접힌 요약 카드 한 줄("확인 필요 7건 — 부족 3 · 미반납 1 …")만 두고, 탭하면 상세가 펼쳐진다. 출처는 바텀시트로 열람.

- 장점: 가장 정갈하고 조용한 리서치 도구 감성. 신뢰형 챗봇이라는 제품 정체성이 제일 또렷함. 폰 세로에서도 동일 경험.
- 단점: 위험 정보가 한 번 접혀 있어 "지금 뭐가 문제인가"를 보려면 탭 1회가 필요. 라운딩 중 흘끗 보는 용도로는 약함.

## Style B — Split Ops (`style-b-split-ops.html`)
**태블릿 가로 2분할.** 좌측 챗, 우측에 실시간 상태판 + 인용 근거 패널을 상시 노출(NotebookLM 태블릿 2-pane 계승). 챗의 [n] 칩을 탭하면 우측 근거 패널이 하이라이트로 갱신된다. 엑셀 테이블은 소스&데이터 탭에서 **전체화면 오버레이**로 열리고, 셀 수정 시 pill형 diff 바(전→후·사유·승인)가 뜬다. 900px 미만(폰)에서는 우측 패널이 접힌다.

- 장점: 카트 위 가로 거치 태블릿에 최적 — 챗을 쓰면서도 위험 항목·근거가 항상 시야에 있음. 근거 상시 노출은 NotebookLM의 신뢰 UX를 가장 잘 살림. 테이블 오버레이는 넓은 화면을 온전히 써서 대량 편집에 유리.
- 단점: 폰 세로에서는 우측 패널이 사라져 A와 비슷해짐(별도 폴백 필요). 구현 분기(2-pane/1-pane)가 가장 많음.

## Style C — Command Chat (`style-c-command-chat.html`)
**운영 인지 최우선.** 챗 입력창 바로 위에 상태 카운터 칩(부족 3 · 미반납 1 · 기한임박 2 · 미처리 1)을 **항상 고정 노출**, 한 번 탭으로 해당 목록이 인라인 확장되고 "보충/반납/인계 →" 빠른 액션이 붙는다. 전체적으로 밀도를 한 단계 높였다.

- 장점: 입력창을 볼 때마다 위험 카운터가 함께 보임 — 타이핑 직전이 가장 시선이 모이는 곳이라 현장 인지 효과가 최대. 폰 세로에서도 구조가 그대로 유지됨(반응형 분기 최소). 칩 → 확장 → 액션 동선이 짧음.
- 단점: 순정 NotebookLM의 "조용함"에서 가장 멀다. 카운터가 0건일 때도 칩 행이 자리를 차지함(0건 시 자동 숨김으로 보완 가능).

## 추천안

**Style C를 기본으로, 태블릿 가로(≥900px)에서만 B의 우측 근거 패널을 추가**하는 혼합을 추천한다.

근거: ① 이 앱의 1순위 사용자는 카트를 밀며 틈틈이 확인하는 현장 근무자 — "지금 뭐가 문제인가"가 탭 없이 보여야 하고, C의 고정 카운터가 그 요구를 가장 싸게 해결한다. ② C는 폰/태블릿 세로에서 분기 없이 동일하게 동작해 구현·유지보수가 가장 단순하다. ③ 다만 근거 상시 노출(B)의 신뢰 UX는 태블릿 가로에서 공간이 남을 때 켜는 점진적 확장으로 얻을 수 있다. 순정 감성(A)을 최우선으로 두고 싶다면 A 단독도 무리가 없다 — 상태 강도만의 차이라 이후 전환 비용도 작다.

**결정 대기**: A / B / C / 혼합(추천안 또는 다른 조합) 선택 시 HANDOFF.md에 기록 후 구현을 시작한다.
